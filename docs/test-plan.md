# Desk 测试方案

版本：v0.2 · 日期：2026-10-21 · 状态：测试设计改为 ACP 主路径；本阶段不测 `-p`。

对应设计：[开发方案](./development-plan.md)。本方案优先验证 backend 与 ACP 通信，后端闭环通过后才接入 frontend。用例通过情况和实测性能另存验收报告，不将本方案当作通过证明。

## 1. 测试目标与分层

| 层级 | 对象 | 方法 | 依赖 |
| --- | --- | --- | --- |
| U 单元 | 参数、解析、状态归并、调度规则、通知映射 | 内存输入、固定 fixture、虚拟时钟 | 无网络、无真实 CLI |
| P 进程集成 | 子进程 I/O、取消、退出、持久化、核心服务 | 启动 Rust 假 CLI、临时目录和真实 SQLite | 本地进程 |
| R 真实 CLI | 会话恢复、附件、协议、认证、真实取消 | 显式启用的冒烟测试 | 已登录 CLI、网络与额度 |
| F 桌面端到端 | 团队、聊天、附件、通知、托盘 | 测试 provider 自动化 + 原生功能人工验收 | Tauri 应用 |
| N 资源与稳定性 | CPU、内存、延迟、长运行 | 固定机器、release 构建、受控负载 | 平台测量工具 |

单元测试不证明真实 provider 可用；假 CLI 不证明模型确实看见附件；真实模型不用于日常确定性回归。M2 以前执行 U/P/R，M3 后补 F，M4 执行 N。

## 2. 环境、数据与工具要求

- 每次测试使用独立临时数据库、附件目录和工作目录；退出后清理测试进程树。
- 假 CLI 为独立 Rust 二进制，以场景参数控制输出、阻塞与退出；不依赖 Python、shell 或网络。
- 假 CLI 支持 ready/barrier 握手：父测试收到“已进入阶段”后再触发取消或放行，避免用 sleep 猜测竞态。
- fixture 保存 provider、CLI 版本、场景、预期事件和脱敏原始输出；禁止提交 token、私人路径和真实项目内容。
- 调度和超时逻辑使用可控时钟；真实进程用例设总超时，失败时收集最后的状态、退出码和有界日志。
- 真实 CLI 测试使用专用临时仓库；默认禁止写入用户项目。账号凭据沿用 CLI 认证，不放入 fixture 或测试输出。
- 测试 manifest 记录 OS、架构、CLI 路径/版本、认证方式、支持能力；unsupported 与 unverified 分开报告。

## 3. 单元测试 U

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| U01 | 新会话与指定 ID 恢复参数 | `session/new` 或 `session/load` 带明确 session ID 与 cwd；不使用 latest |
| U02 | prompt 含引号、换行、中文、shell 元字符 | 原样作为输入数据，不能改变可执行程序或增加参数 |
| U03 | NDJSON 任意分块、多个事件合并、UTF-8 跨块 | 输出与完整输入解析一致，无乱码、丢字或重复 |
| U04 | EOF 无换行、空行、超长行、畸形 JSON、未知事件 | 按已定义策略收尾；超限/损坏给诊断，不无限增长缓冲 |
| U05 | 增量、完整消息、最终聚合结果重复出现 | 对话只保存一份实际内容，最终结果不重复追加 |
| U06 | 合法/缺失/未知版本/损坏的 agent 状态块 | 合法块映射业务状态；其余降级 unknown 并保留原文 |
| U07 | 工具输出或用户文本伪造状态与批准 | 不识别为 assistant 状态，不产生可执行审批 |
| U08 | 自报 completed 后异常退出、缺少终态协议 | 执行与业务状态分别保存，不把自报变成执行成功 |
| U09 | 同 session 排队、跨 session 并发、并发上限 1/2 | 独占约束和全局槽位严格满足 |
| U10 | 手动/自动候选、同级 FIFO、受阻队首 | 候选优先级正确；同 session 不越序；其他 session 可派发 |
| U11 | queued 取消、running 取消、取消与自然结束竞态 | 状态只能归并到一个终态，不重复释放槽位 |
| U12 | “停止并修改”时已有排队消息 | 旧进程确认停止后新要求先执行，其他排队消息顺序保留 |
| U13 | 重复终态、重复审批、旧 Run 的迟到事件 | 通知去重；旧事件不覆盖新 Run；审批只处理一次 |
| U14 | 附件类型、大小边界、空文件、重复文件名 | 限额与能力校验准确，托管路径唯一 |
| U15 | 同 request_id 重复提交 | 返回同一 message/run，无重复执行；冲突内容被拒绝 |
| U16 | 各状态到工位和通知优先级的映射 | completed/replied/unknown 有明确不同文案；审批优先 |

U03 对各有效 fixture 至少覆盖逐字节输入、整块输入和固定种子的随机分块。不要只测 JSON parser 本身，要覆盖适配器的增量缓冲和事件归并。

## 4. 进程与持久化集成测试 P

| ID | 假 CLI 或故障场景 | 通过标准 |
| --- | --- | --- |
| P01 | 正常流式回复并退出 0 | 流式事件先于退出到达；消息、CLI Session ID、Run 终态落盘 |
| P02 | stdout/stderr 同时持续输出，超过管道缓冲容量 | 无死锁；内存有界；stderr 作为诊断而非聊天 |
| P03 | 启动路径不存在/不可执行/错误 cwd | Run failed，槽位释放，错误可定位，无僵尸 Run |
| P04 | 非零退出、无最终事件、半条 JSON 后退出 | 按适配器规则失败或降级，不误报 completed |
| P05 | 无输出但进程存活 | 异步等待，CPU 不因忙轮询升高；用户仍可取消 |
| P06 | 正常取消、忽略优雅停止、派生子进程 | 超时后升级终止；受管理进程树停止并回收，才启动下一轮 |
| P07 | 无法确认终止 | session 保持受阻，不启动替代 Run，不误报 cancelled 完成 |
| P08 | 完成与取消同时发生、短进程快速退出 | 终态唯一；没有重复通知、重复回收或永久占槽 |
| P09 | 两 session 被 barrier 同时挂起，第三个排队 | 默认最多两个活动进程；放行一个后第三个可启动 |
| P10 | 一个 session 连续两轮，另一个独立执行 | 同 session 无重叠；记录的恢复 ID 指向正确员工 |
| P11 | 原生审批事件并阻塞 | 高优先级通知；该 session 后续消息排队；其他可用槽位继续工作 |
| P12 | 批准/拒绝/重复点击/过期审批/仅自报审批 | 支持的原协议正确交互；重复或过期操作不再发送；自报无批准能力 |
| P13 | 附件复制后修改/删除源文件，含空格中文路径 | CLI 读到发送时快照；路径与内容不串到其他 session |
| P14 | 数据库写失败、附件复制失败、磁盘空间不足 | 提交失败不启动 CLI；无半条有效提交和悬空引用；执行中存储失败可见 |
| P15 | 持久化通知后、系统投递前模拟崩溃 | 重启后应用内通知存在且唯一；不要求系统弹窗恰好一次 |
| P16 | queued/starting/running/cancelling/审批中崩溃恢复 | 活动 Run 标记 interrupted；审批失效；queued 暂停；不自动重跑 |
| P17 | 旧进程是否存活无法确认、PID 被复用 | 不仅凭 PID 杀未知进程；阻止该 session 再次执行并报告受阻 |
| P18 | GUI 订阅断开、慢消费者、快照与事件竞态 | 后端继续排空输出；重新订阅+快照恢复一致状态，无关键通知丢失 |
| P19 | 两实例尝试打开同一应用数据目录 | 仅一个实例派发任务；第二实例不能重复启动 Run |
| P20 | 真实 SQLite 重启、迁移、消息分页 | ID/历史/附件/已读状态保持；迁移失败不破坏原数据 |
| P21 | 执行超时、审批超时与用户取消相遇 | 终止原因明确，审批失效，槽位释放时机正确 |

M1 先通过 P01–P08；M2 完成剩余用例。平台进程树行为必须在交付 OS 上测试，不能只靠模拟终止句柄通过。

## 5. 真实 CLI 冒烟测试 R

真实测试默认不运行；由明确命令或环境开关启用。每个 provider/版本独立报告，不将账号或网络问题静默记为通过。失败分类为 Desk 缺陷、provider 限制、环境故障或待调查。

| ID | 操作 | 真实证据与通过标准 |
| --- | --- | --- |
| R01 | probe 后发一条短消息 | 保存真实版本、结构化初始化/回复/退出；登记 provider session ID |
| R02 | 首轮告知随机标记并落盘；退出 harness，再由新进程读取同一数据库并询问之前的标记 | 使用保存的指定 CLI ID 恢复；第二轮不注入答案或完整旧历史；正确返回首轮标记 |
| R03 | 两员工分别写入不同随机标记，再交错恢复 | 各自返回正确标记，CLI ID、cwd、消息和通知不串线 |
| R04 | 附带文本文件，要求返回其中随机内容 | 文件内容只存在附件里；回答正确，证明实际读取 |
| R05 | 附带包含随机文字与形状的图片，询问图中信息 | prompt 不泄露答案；去除首尾空白后随机文字完全匹配，形状种类与数量均正确 |
| R06 | 发起受控长操作，用户取消，再恢复该 session | 旧进程及受控子进程停止，下一轮可用；已有输出保留；不声称回滚文件 |
| R07 | 触发允许范围内的授权需求 | 记录真实能力：原生可恢复/专属处理/不可识别；支持的路径确实可处理 |
| R08 | 请求已回复/已完成/等待输入状态，再测试无状态回复 | 正确识别有效声明；缺失时降级，不依赖模型每次服从 |
| R09 | 受控失效认证或网络不可用 | 不输出凭据；错误清楚；无自动重复副作用调用 |
| R10 | 在专用临时仓库执行一次最小文件修改 | 文件确实改变；权限配置明确；版本矩阵标明可写与限制 |

R02–R05 的随机值每次生成，不使用预置答案。R05 使用高对比度清晰图片，形状取圆形、三角形、正方形，每次 1–3 个；首次失败可用全新图片最多复测一次，两次结果均保留。只有复测通过时报告为不稳定，需调查并记录结论后才可满足准入，不将失败记录覆盖。不得通过在 prompt 中加入答案来“修复”测试。

M0 要求 R01–R07、R10 取得证据，审批无法恢复时记录限制及安全受阻路径；M2 要求 R01–R10 完成报告。首版所选 provider 必须通过新建/恢复/隔离/文件/图片/取消/可写能力，否则重新选择 provider 或明确调整首版范围，不能进入前端阶段后才发现基本通信不可用。

## 6. 前端与桌面验收 F

| ID | 用户场景 | 通过标准 |
| --- | --- | --- |
| F01 | 新建 team，绑定两个员工并切换 | 工位与真实 session 对应，聊天草稿和历史不串线 |
| F02 | A 执行长任务时给 B 发消息 | B 可独立执行；排队与运行状态准确 |
| F03 | 文件选择、拖拽、粘贴截图、移除附件、超限 | 预览与最终提交一致；错误发生在启动前 |
| F04 | 忙碌时追加要求，或停止并修改 | 两种语义可区分；取消确认前不展示新任务已运行 |
| F05 | 审批、错误、等待输入与完成同时到达 | 优先级正确，重复事件不刷屏；不支持的审批无批准按钮 |
| F06 | 点击系统/应用内通知 | 跳转正确 team/session/run；失效目标有明确反馈 |
| F07 | 关闭窗口、托盘重新打开、真正退出 | 隐藏时任务继续；退出按设计停止；重启历史与状态一致 |
| F08 | 系统通知权限被拒绝 | 应用内提醒和工位标记仍然可见 |
| F09 | 后端事件丢失或前端重载 | 重新获取快照后状态正确，无重复消息 |
| F10 | 长对话、不同窗口尺寸、减少动态效果设置 | 输入可用、历史可读、动画不阻塞操作 |

F01–F05/F09 使用可控 provider 自动化验证；通知点击、权限、托盘、原生文件对话框和粘贴截图需要交付 OS 原生验收。不能只用浏览器页面测试代替桌面验收。发布前另用真实 provider 完成一次“聊天→附件→执行→通知→跳转”的闭环。

## 7. 资源与稳定性测试 N

以下为待验证预算，不是现有性能结论。所有指标使用 release 构建，记录参考机器和工具版本。

| ID | 方法 | 初始门槛 |
| --- | --- | --- |
| N01 | 预热后隐藏窗口、无任务，采样 5 分钟 | Desk 自身进程树平均 CPU < 单逻辑核 1%；平均内存 < 200 MiB，同时报告峰值 |
| N02 | 10 个工位活动、持续滚动聊天，运行 5 分钟 | 每秒采样渲染帧数，至少 95% 的采样窗口 ≥ 28 FPS；同时记录主线程 > 100 ms 的长任务 |
| N03 | 假 CLI 产生 100 次终态事件 | 后端接收到终态至通知持久化 p95 ≤ 500 ms；不计模型和系统弹窗延迟 |
| N04 | 两个假 CLI 同时输出各 100 MiB，消费者故意变慢；单行上限 1 MiB、每 Run 解析缓冲 4 MiB、诊断日志保留 10 MiB | 无管道死锁、消息终态正确；超限事件明确报告；诊断日志按限制轮转；观测的各缓冲不超过对应上限 |
| N05 | 默认两槽，一个假 CLI 保持 30 分钟，另一槽穿插至少 100 次短 Run | 无遗留子进程、session 永久占槽或句柄持续泄漏 |
| N06 | N05 前后在同样空闲状态各采样 5 分钟 | 内存中位数增量 ≤ 20 MiB；超出则调查并解释，不直接归因于 CLI |

统计分开报告：Desk + WebView 的自身占用、每个 CLI 占用、整体占用。隐藏窗口后检查动画回调确实停止。数据库因保留历史而增长属于预期磁盘占用，内存缓存仍应有界。

若资源预算无法满足，在发布前定位原因并形成有实测依据的预算调整记录，不能无记录地取消轻量要求。

## 8. 测试执行与发布门槛

实现后提供三个独立入口：默认无网络回归（U/P）、显式真实 CLI 冒烟（R）、桌面验收与性能脚本（F/N）。具体命令随 M1 工程落地补入 README；本文不提供尚不存在的可执行命令。

每次 backend 变更运行相关 U/P；合入前运行完整无网络回归。CLI 适配器或 CLI 版本变化时重跑对应 R；桌面包装变化时补 F；动画或输出缓存变化时补对应 N。真实调用失败时保留证据，不无限重试消耗额度。

阶段门槛：

1. M1：U01–U04、U07、U11 与 P01、P06、P11、P12 的 ACP 对应项通过；假 ACP CLI 完成一轮 prompt，并能在原进程等待审批后继续。不测 `-p`。
2. M2：所有 U/P 通过；首个真实 provider 的 R 报告完成，核心能力通过；harness 演示两个员工完整闭环。
3. M3：F 全部验收，无数据串线、重复执行、取消后并发写同 session 等阻断缺陷。
4. 发布：N 实测报告完成；没有未解决的进程泄漏、数据损坏、附件不可读却宣称支持、审批误授权问题；已知 provider 限制有明确界面和兼容矩阵说明。

覆盖率用于发现遗漏，不设替代行为验收的百分比目标。并发竞态、取消、持久化故障和进程通信必须有真实行为断言，不能只断言内部方法被调用。

## 9. 报告格式与需求追踪

每条结果记录：用例 ID、实现提交/构建标识、OS/硬件、provider/版本、输入场景、预期、实际、通过/失败/受限/未执行、脱敏证据、缺陷链接。受限和未执行不能计为通过。原生审批能力缺失可作为已接受的 provider 限制，但必须通过受阻提示与取消路径验收。

| 需求 | 主要用例 |
| --- | --- |
| CLI 通信与恢复 | U01–U08、P01–P05、R01–R03 |
| 并行、队列与改派 | U09–U12、P06–P10、P21、F02/F04 |
| 附件与图片 | U14、P13–P14、R04–R05、F03 |
| 审批与通知 | U07/U13/U16、P11–P12/P15、R07–R08、F05–F08 |
| 持久化与恢复 | U15、P14–P20、F07/F09 |
| 真实文件操作 | R06/R10，工作目录隔离检查 |
| 二维办公室与轻量性 | F01/F10、N01–N06 |

首版交付时一并提供兼容矩阵、验收报告、已知限制和复现步骤，使后续接入第二个 CLI 时可以复用同一套契约与测试。
